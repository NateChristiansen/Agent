# Obsidian as the front end

This repo is an Obsidian vault. Obsidian is where the owner reads, writes, and runs sessions. The
CLI owns the generated files, the vault-facing ones included
([[adrs/0004-obsidian-front-end|ADR-0004]]).

## What the harness generates for the vault

| Path | What | Regenerated by |
|---|---|---|
| `Dashboard.md` | home note: the plugin pane shows Needs you, Managers, Workers, Open features, Open tasks and collapsed Health. Journal, log and navigation use DataviewJS | `status_render` tool, only when the layout changes |
| `Index.md` | compact linked views for open and closed features, decisions, docs (retros, design, audits, QA plans), handoff history, and the past 30 days of journal notes | `status_render` tool |
| `.agent/live.json` | the live pane's snapshot: managers, workers, leases, owner actions, tabs and health. Gitignored, never a note | the `activity` and `session-start` hooks, the supervisor (attempt start, end, a 5 s heartbeat), `status render` |
| `.agent/status.json` | canonical feature counts and indexed open-task text, from `features.list_tasks` | every task add, done, undo and supersede; `status render` |
| `features/*/orders/<dispatch-id>.md` | the complete composed work order, written through the notes writer before an approval preview; synced with the notes | dispatch preview or direct launch |
| `harness/obsidian/views/*.js` | the `dv.view` scripts: `features` (Dashboard and Index open feature cards), `index` (compact linked records), `nav`, `tasks`, `log`, `worker` (a handoff's live tail), `feature` (a plan's header), `handoffs` (a plan's handoff table), `journal` (daily notes in a table that wraps). They read and format; every rule stays in Python | tracked source, edited by hand |
| `bases/features.base` | views over `features/*/plan.md` frontmatter: Open, Board (cards by status), Closed, All | `status_render` tool |
| `bases/adrs.base` | Current and All views over `adrs/*.md` | `status_render` tool |
| `bases/journal.base` | Recent daily notes with full columns | `status_render` tool |
| `bases/handoffs.base` | Running, Live, Done, All and Rubric views over handoff frontmatter | `status_render` tool |
| `bases/docs.base` | Recent, Retros, Design, Audits and QA plans | `status_render` tool |
| `features/*/log.md` | entries are typed callouts (`> [!decision] 2026-09-03 11:24`) styled by the snippet | `log` tool |
| `tags:` / `links:` frontmatter | Feature plans link to public harness ADRs and private work decisions; public ADRs have no private backlinks | `feature_new` and `adr_new` tools |
| `.obsidian/` curated config | see [[docs/07-working-in-obsidian|the Obsidian chapter of the manual]] | `bin/agent obsidian setup` |

None of these are hand-edited. The protect hook denies a hand edit and names the command to
use instead.

## Setup and plugins

Setup, the plugin list and the settings left to set by hand are in the manual:
[[docs/07-working-in-obsidian|docs/07-working-in-obsidian.md]]. For a live rollout of `agent-terminal-focus` without a

## Workers and tab labels (ADR-0015)

- **Open a worker.** A Workers row's Open link runs the `agent-worker-open` Shell commands
  entry, which runs `bin/agent dispatch open <id>`. A split Terminal tab opens on the worker:
  `dispatch watch --follow` while it runs, `claude --resume` in its worktree once it stops. It
  goes through the Obsidian CLI (`obsidian eval`) and the Terminal plugin's view state, which is
  undocumented. Reload Shell commands after its `data.json` changes.
- **Label tabs.** Hooks relabel Terminal tabs through the plugin's rename path. A manager's tab
  reads `<icon> NNN slug · cl|cx <id>`, or `<icon> my-name · cl <id>` with no
  feature number when the owner named the session. The slug or owner-chosen name is capped at
  18 characters. The icon is `✋` while it waits on you, `⏳` while a worker or background task
  runs, `⚙️` while working, and `✅` when idle. A watch tab reads `◐`, `✳` or `✋ <id> watch` by
  the worker's state. A resume tab carries no label. `AGENT_NO_TABS=1` or `.agent/tabs-off`
  turns labels off. `?` after the icon means the last snapshot is unconfirmed after three
  consecutive stale polls, at least 2 s apart. Fresh activity clears it. An open owner question
  keeps its hand until answered, including on older plugins. A live worker supervisor sets a 15 s window; otherwise it is 12 h. Finished
  results stay in the Dashboard's Managers "owes N" count, rather than a `+N` on the tab.
  Codex approvals show `✋` after 20 s unresolved; owner questions show it immediately. Peer
  requests with an expected reply and scheduled session wakes show `⏳` while pending.
- **Who paints.** The `agent-terminal-focus` plugin paints every tab from `.agent/live.json`
  every 2 s; `obsidian eval` from a background drainer paints only while the plugin is down, or
  has yielded because a snapshot write failed (`.agent/live-failed/`). Each write records an
  intent there first. If its writer dies before publishing, the plugin yields 10 s later and
  `status check` fails. A write that changes an owner question or approval has a watchdog. It
  starts the drainer while the writer stalls and republishes once the writer dies. `status
  check` also fails after a write runs past 30 s. A plugin build older
  than that yield cannot be told to stop, so it may repaint the stale snapshot over the
  fallback until `bin/agent setup` installs the current build; `status check` fails and
  doctor warns while one runs.
- **Check a tab from another session.** A session that checks its own tab through a command
  needing approval fires `PermissionRequest`. Claude shows `✋` immediately; Codex delays it
  20 s, and a tool result or Stop clears the delay. Read the tab from a different session, or read `.agent/tabs/metrics.jsonl`, which
  records each painted label.

## Live dashboard and health

The `agent-live` code block embeds the live pane in `Dashboard.md`. It reads
`.agent/live.json` and `.agent/status.json` on a file event, with a 2 s poll as fallback for hidden files and missed
events. Rows stay keyed by feature and id. Changed cells patch in place; ages tick without
rebuilding rows. Activity timestamps cannot reorder managers. Deadline fields still control
permission delays and stale states. Handoff links, worker open links, clear leases and orphan
resume commands remain available. Legacy DataviewJS live blocks are retired; use an `agent-live`
code block for live managers, workers and owner actions.

Needs you comes first, followed by Managers, Workers, Open features and Open tasks. Journal and
Log stay below the pane. Feature and task rows use Python's counts and text, including task
numbers; no Dataview index or reload warning competes with them. The Index and older notes'
feature/task scripts read the same status snapshot. If that file cannot be read, the pane keeps
its last rows with a warning; live manager and worker updates continue.

Health is one collapsed line: all ok, or warn/fail/unknown counts. Click it for details. It shows notes-sync lag and its last error, the peer link's last recorded send,
the verify queue, spend today, hook errors, tab-paint failures, render failures and telemetry
coverage. Each signal carries `ok`, `warn`, `fail` or `unknown`, its machine and its age.
A recent partial record is `warn`, even if its count is zero. A signal older than its validity
window becomes `unknown`; enrollment alone does not prove a working peer link.
Missing notes-sync evidence is unknown, including older Windows summaries that labelled
"no sync recorded" as fail. Recorded sync errors still report fail.

## Plan and work-order links

The terminal handler opens HTTP(S) and validated same-vault `obsidian://open` links, opens
in-vault `file://` links in Obsidian, and leaves outside-vault paths copy-only; hand-overs follow
[[AGENTS.md]]. Managers include a plan or
work order's `link` URL in inline code; dispatch previews and launch results return
`work_order_url`. Preview now writes the notes file and a local manifest under
`.agent/dispatches/previews/`, without allocating a worker or taking its slot. Launch keeps
the preview's nonce and exact bytes. Changed order text, launch choices or a hand-edited order
file require a new preview and approval. The launched `.prompt.md` stays available as before.

On each machine after installing the plugin, use reading view mid-page through three task
ticks and a worker transition. Scroll position should hold, and a task count should update
within 5 s. Click a work-order link from a Claude preview and confirm the composed order opens.

Local usage and telemetry records are written on every Stop. Notes publication runs on a
15-minute cadence and flushes at session end. Each machine writes only its own files under
`usage/`, including `usage/telemetry/YYYY-MM-DD.<machine>.json`; the pane reads those summaries.
Spend shows its own completeness. Missing machine days and partial summaries remain incomplete.
An open day's summary is partial until collection covers the day.

`agent telemetry summary --date 2026-10-14` returns fixed counts for a local calendar day.
`--since` and `--until` accept timestamps with UTC offsets for a window. The `harness` tool's
`telemetry_summary` action returns the same JSON, using `date` or `since` and `until`.
It separates owner questions, permission requests, raw waiting transitions and successful
visible hand paints, then reports dispatch spans, verify outcomes, retried flakes and health.
The approver stays unknown. Missing paint records carry `paints_complete: false`; silent losses
cannot be counted. Raw events remain local.

## Daily notes

`journal/YYYY/MM-Month/DD-Weekday.md` is both the Obsidian daily note and the committed record of the day
(`harness/journal.md`): a generated bullet list between markers, `spend_usd`, `manager_usd` and
`dispatches` as properties, and `## Notes`, which is the owner's. `/journal` writes the block and
the properties. The template is the same skeleton, for a note Obsidian creates before the
CLI does. The `journal collect` bundle is scratch for `/journal` and lives under
`.agent/journal/`, outside the notes.

## Caveats

- Several vault folders and files are symlinks into a second, private repo (ADR-0012:
  `features/`, `decisions/`, `journal/`, `usage/`, `notes/`, `harness/owner/`, `harness/voice.md`, `agent.yaml`,
  `.mcp.json`, `bases/`). Obsidian follows them: the
  explorer, search, the graph and the Bases views see one vault, and a note opened through a
  link saves to the notes repo. Two consequences. Git status for those notes is the notes
  repo's, not this one's, so the obsidian-git plugin (pointed at the vault root) does not see
  them: with `notes_sync: on` the harness commits and pushes them at each turn's end (ADR-0034),
  and with it off you commit them in a terminal in the notes repo. And the `harness` tool's `notes_status` action is the
  fastest way to tell whether a folder that looks empty is a broken link rather than an empty
  folder.
- Obsidian watches a symlinked directory but not a symlinked file at the vault root. A CLI
  write through such a link never reaches an open note, and Obsidian saves its stale copy
  back over it. That is why `Dashboard.md` and `Index.md` are plain files
  (ADR-0016); keep any file the CLI writes and Obsidian keeps open out of root-level links.
- Callout colors: `--callout-color` must be a CSS color (hex). Obsidian 1.13 feeds it to
  `color-mix`. The RGB-triplet form in older docs and in the vendored skill's CALLOUTS.md
  renders no color at all.
- Hidden folders cost start time. Obsidian indexes every file a plugin makes visible, and
  `userIgnoreFilters` only hides paths from search, graph and the switcher. With Show Hidden
  Files on, the vault indexes tens of thousands of files (`node_modules` under
  `.agent/mcp-servers`, `.venv`, `.git`) and a start can take most of a minute; with it off, a
  start takes about a second (Settings → General → "Notify if startup takes longer than
  expected" → Check now measures it). So `agent-hidden-files` shows only the five agent folders, and `obsidian setup`
  turns Show Hidden Files off on every run. To see every dot folder, enable Show Hidden Files
  in Settings → Community plugins, and disable it again when done. To change what
  `agent-hidden-files` shows, write `{"show": [...], "skip": [...]}` to
  `.obsidian/plugins/agent-hidden-files/data.json` and reload the plugin; a skip entry with no
  slash matches a folder name at any depth.
- `alwaysUpdateLinks` is off because the CLI owns links in generated files. Renaming or
  dragging a feature folder or ADR inside Obsidian leaves `links:` dangling, and nothing reports
  it. There is no rename command: a feature or an ADR keeps the name it was created with
  ([[AGENTS#Standing rules]]).
- `adrs:` and `decisions:` on a feature list public harness ADRs and private work decisions.
  The same relations are in `links:` as link pills. The CLI writes both fields. A public ADR never links back to the private feature.
- The daily note is committed, block included. The `journal collect` bundle it is
  drafted from is gitignored scratch and can carry prompt heads and work-item subjects. The
  block itself is verified before it is written (`/journal` step 3), and `## Notes` is never
  generated.

- Obsidian rewrites `app.json`, `appearance.json`, `core-plugins.json`, and
  `community-plugins.json` on start. Key order can churn in git. Content does not.
- `workspace.json` and plugin binaries are gitignored. `setup` is safe to re-run.
- The Properties panel rewrites frontmatter on save. A bad `status`, a dangling link or a missing
  type tag surfaces when the CLI next reads the file; nothing prevents them.
- Never edit `Dashboard.md`, `Index.md`, `bases/`, `adrs/README.md`, `decisions/README.md`,
  `features/*/log.md`, or `.agent/raw/` in Obsidian. Use the palette actions or a terminal
  tab.
- `harness/voice.md` and `harness/owner/rules.md` are yours. Edit them anywhere.
