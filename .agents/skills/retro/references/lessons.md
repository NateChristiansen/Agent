# Retro lessons

Read with `/retro`. These incidents explain its verification and calibration steps.

## Verify a lower-tier reading against records

A transcript reader's counts of command-chain denials did not match the records. It also assigned hook denials to a callback that documentation limited to auto mode.
Re-derive every number and mechanism claim from the records before putting it in the retro,
and state which claims were verified.

## Compare the stated rubric row with the work done

An early build ran under a "review row" justification meant for wording judgment, while the agent wrote code, hooks, a tool and tests. Check the
actual work against each subagent's stated model and effort row, not just whether a row was
named.

## Revisit calibration rows after more attempts

A mechanical dispatch was recorded as one clean attempt while still in flight. Its record
later showed three attempts and an overrun, followed by several times that cost in further
dispatches. Compare existing feature rows with final dispatch records and correct changed
cost, attempts and outcome instead of only appending new rows.

## Follow a task's pointer before calling it unfinished

A manager treated one unticked task as unfinished and began to investigate. The task pointed to
another feature's log, which already held the root cause, the fix commit, the regression
coverage and the owner's live verification. When an unticked task names another feature, log or commit, read that record first. Then
report the task as finished elsewhere, or as open with what is missing.
